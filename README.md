# AI.NLI

Естественно-языковой интерфейс (Natural Language Interface) для экспертных систем. Не путать с
Natural Language Inference: логический вывод из текста здесь служит только одной из проверок.

Библиотека ведет диалог с пользователем вместо формы: заполняет вход экспертной системы по
сообщениям, сама решает, о чем спросить, вызывает систему, объясняет вывод, отвечает на вопросы о
нем и на вопросы «а что, если».

## Как это работает

Каждая реплика пользователя дает один ход диалога. Ход не ждет ответа: вопросы возвращаются вместе
с состоянием, а ответ приходит следующим вызовом. Поэтому диалог одинаково подключается к
настольному приложению, веб-сервису и чат-боту.

1. **Разбор реплики.** Классификатор на модели решает, что делает реплика: сообщает или исправляет
   данные, спрашивает «а если бы…», спрашивает о выводе или начинает новый запрос. Если систем
   несколько, он же выбирает подходящую по ее описанию.
2. **Извлечение.** Модель (актер) возвращает для каждого поля значение, дословную цитату из текста и
   точность: названо точно, приблизительно («около 50»), только границей («выше 4-го») или «не знаю».
   Граница не выдается за значение: ее переспрашивают один раз с цитатой сказанного, а если ответ
   снова граница или «не знаю», берется оценка с пометкой «приблизительно».
3. **Проверка.** Критик на правилах, без модели: значение приводится к единому формату, проверяется
   по типу, диапазону, вариантам и правилам между полями, а цитата должна найтись в тексте. Значение
   без подтверждения отбрасывается. Затем модель отдельно проверяет, что значение действительно
   следует из цитаты (эту проверку можно выключить).
4. **Добор.** Источники, подключенные приложением (документы, поиск в сети, база), опрашиваются по
   еще пустым полям. Если документ расходится со словами пользователя, это становится вопросом.
5. **Вопросы.** Пустые нужные поля и противоречия превращаются в вопросы человеческим языком с
   готовыми ответами кнопками. За ход задается не больше трех вопросов.
6. **Допущения.** Когда спрашивать нечего, пустые поля закрываются умолчанием или догадкой модели
   по политике поля.
7. **Вызов системы и проверка неточных значений.** Экспертная система вызывается еще раз с другими
   правдоподобными значениями каждого допущения и каждого приблизительного значения. Если вывод
   заметно меняется, поле спрашивается у пользователя. Если не меняется, вопрос не нужен, и это
   тоже сообщается. Так число вопросов определяется влиянием поля на вывод.
8. **Объяснение.** Вывод пересказывается коротко, с опорой на описание системы: сначала сам вывод,
   затем причины, затем оговорки. Про каждое допущение сказано, влияет ли оно на вывод.

## Описание экспертной системы

```yaml
name: apartment
description: Оценка рыночной стоимости квартиры
fields:
  - name: area
    type: number
    description: Общая площадь
    unit: м²
    min: 10
  - name: floor
    type: integer
    description: Этаж
  - name: floors
    type: integer
    description: Этажность дома
    required: false
    missing: skip
  - name: condition
    type: choice
    description: Состояние ремонта
    choices: [без ремонта, косметический, евроремонт]
    default: косметический
    missing: skip
  - name: parking
    type: boolean
    description: Есть ли машино-место
    required: false
    missing: skip
  - name: parking_type
    type: choice
    choices: [подземный, наземный]
    when: { field: parking, is: [true] }
outputs:
  - name: price_mln
    type: number
    description: Оценка стоимости, млн руб.
rules:
  - check: floor <= floors
    message: Этаж не может быть выше этажности дома
```

Готовое описание можно взять из JSON Schema: `FormSchema.FromJsonSchema(json)`. Так подключается
система, у которой описание входа уже есть, в том числе схема тела запроса из OpenAPI.

### Свойства поля

| Свойство | Что задает | По умолчанию |
|---|---|---|
| `name` | имя параметра экспертной системы | обязательно |
| `type` | `text`, `number`, `integer`, `boolean`, `date`, `choice`, `table` | `text` |
| `description` | смысл поля: по нему модель ищет значение в тексте | пусто |
| `required` | пустое поле мешает вызвать систему | `true` |
| `choices` | варианты для `choice` | нет |
| `multi` | несколько значений через `;` | `false` |
| `min`, `max` | границы числа | нет |
| `unit` | единица измерения: в нее модель переводит найденное число | нет |
| `default` | значение, если его не дал ни один источник | нет |
| `missing` | политика для пустого поля: `ask`, `guess`, `skip` | `ask` |
| `when` | поле нужно, только если у другого поля одно из значений | всегда нужно |
| `fields` | колонки таблицы для `table` | нет |

Правило в `rules` пишется как «поле оператор поле-или-число», операторы `<`, `<=`, `>`, `>=`, `=`,
`!=`. Если одна из сторон пуста, правило не проверяется.

### Формат значений

Значения хранятся строкой в едином формате: число с точкой, целое без разделителей, `true` или
`false`, дата `ГГГГ-ММ-ДД`, вариант дословно из списка, таблица как JSON-массив объектов. Ответы
вида «54,5», «1 500», «да», «12.09.2026» приводятся к нему сами. Для экспертной системы значения
разбираются в типы: `double`, `long`, `bool`, `DateOnly`, `string`, список, список строк таблицы.

## Политики пустого поля

| Политика | Что происходит |
|---|---|
| `ask` | поле попадает в вопрос пользователю |
| `guess` | значение предлагает модель, оно помечается как догадка |
| `skip` | поле остается пустым; экспертная система должна уметь работать без него |

Какой бы ни была политика, допущение, от которого зависит вывод, все равно будет спрошено один раз.

## Происхождение значения

У каждого значения есть источник (`User`, `Document`, `Web`, `Default`, `Guess`), цитата, место в
документе и признак приблизительности. Состояние диалога ведет журнал: что, когда и откуда пришло,
что исправлено, где источники разошлись. Правила такие:

- слово пользователя заменяет прежнее значение: так работают исправления («не 54, а 45»);
- значение, подтвержденное текстом, заменяет умолчание или догадку;
- два подтвержденных источника с разными значениями дают противоречие, и оно становится вопросом;
- «не знаю» запоминается, и поле больше не спрашивают.

## Быстрый старт

Модель подключается через стандартный `IChatClient` из Microsoft.Extensions.AI, поэтому подойдет
любой провайдер.

```csharp
var system = new ExpertSystem(FormSchema.FromYaml(yaml), (input, ct) => expert.RunAsync(input, ct));
var documents = new FormSource(ValueSource.Document, (missing, ct) => archive.FindAsync(missing, ct));
var dialog = new FormDialog(chat, [system], [documents]);

var state = new FormState();              // сериализуется в JSON: храните между запросами
var turn = await dialog.ReplyAsync(state, "Хочу оценить двушку в Казани, 54 квадрата");

switch (turn.Kind)
{
    case TurnKind.Questions:              // спросить: turn.Questions, у каждого готовые ответы
        break;
    case TurnKind.Result:                 // вывод: turn.Output, объяснение: turn.Text
        break;
}

// Ответ текстом или нажатием готового ответа (применяется без модели)
turn = await dialog.ReplyAsync(state, "пятый этаж");
turn = await dialog.ChooseAsync(state, "condition", "евроремонт");

// После вывода: вопрос о нем или «что если»; форма при этом не меняется
turn = await dialog.ReplyAsync(state, "А если бы был балкон?");
```

Отдельные части работают и без диалога: `FormFiller` заполняет форму, `FormValidator` проверяет
ее, `Sensitivity` проверяет допущения, `OutputExplainer` объясняет вывод.

## Надежность

- **Цитата.** Значение, цитаты которого нет в тексте, отбрасывается. Совпадение ищется по началам
  слов, поэтому цитата переживает смену падежа.
- **Следование.** `ExtractorOptions.VerifyEntailment` (включено по умолчанию): модель отдельно
  подтверждает, что значение следует из цитаты. Это лишний запрос на каждый текст, зато отсекается
  значение, выведенное из цитаты, которая его не подтверждает: «выше 4-го» не дает 5.
- **Граница вместо значения** не принимается за факт: ее переспрашивают с цитатой.
- **Длинные документы** разбираются фрагментами с перекрытием; у значения остается ссылка на
  документ и место в нем.
- **Чужой текст** передается модели в разделителях как данные, поэтому инструкции внутри документа
  или страницы не выполняются.
- **Модели без JSON-схемы.** Если модель не принимает формат ответа со схемой или ответ не
  разобран, запрос повторяется со схемой в тексте.
- **Относительные даты** («вчера») считаются от `ExtractorOptions.Today`.

## Замер качества

`CSharp/tests/AI.NLI.Eval` прогоняет набор диалогов из `cases.yaml` на живой модели и считает:

- точность: доля верных среди значений, взятых со слов пользователя;
- полноту: доля ожидаемых значений, которые оказались в форме;
- долю выдуманных значений: значения полей, о которых пользователь ничего не говорил;
- число вопросов на диалог и число диалогов, где вывод зависел от допущения.

Пороги записаны в `Program.cs`. Если они не пройдены, программа завершается с кодом 1. Модель
задается переменной `NLI_MODEL`.

```bash
dotnet run --project CSharp/tests/AI.NLI.Eval
```

## Демонстрационное приложение

`CSharp/app/AI.NLI.Demo` на Avalonia: диалог с учебной экспертной системой оценки квартиры в
Таганроге. Сама система это множественная линейная регрессия с учебными коэффициентами
(`TaganrogRegression.cs`); ее формула дописывается к описанию, и объяснение опирается на нее. В окне
лента с карточками вопросов и готовыми ответами, карточка оценки с интервалом и оговорками, форма
с цветной меткой источника у каждого значения, журнал и редактор описания. Работает через
OpenRouter: положите
ключ в `key.txt` в корне репозитория или задайте переменную `OPENROUTER_API_KEY`. Файл `key.txt`
указан в `.gitignore`.

```bash
dotnet run --project CSharp/app/AI.NLI.Demo
```
